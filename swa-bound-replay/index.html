SWA Replay流程

长 Prompt prefill · PCP · cut=20（L21 开始 replay）· W=4 · token 级示例；实际 prefix cache 通常按 block 对齐

同一个自回归主干，按 PCP 执行职责分成因果编码段与 Replay 解码段。 PCP 把长 Prompt 的 prefill token 分片到多个 rank，以降低首 token 时延； L0–L20 负责完整上下文的因果编码并生成共享长历史 KV； L21–L39 负责窗口行 Replay 解码。40 层都使用因果注意力， 但两段在 PCP 执行中的 token 行范围与 KV 角色不同。 这里的 Encoder / Decoder 是执行功能分段， 不是 BERT/T5 式的两套独立网络。

例：可缓存 KV 命中 t0–t11；bounded replay SWA 不复用这段前缀， 所以 L0–L20 执行命中前缀最后 4 行 t8–t11，再执行未命中后缀 t12–t15。

Replay 开启只关闭 bounded-replay SWA 组的这段前缀复用；可缓存 KV 与长历史 KV 仍可命中。Replay 支撑区的可缓存 KV slot 使用 PAD_SLOT_ID 占位，不重写已有 KV； 只有当前后缀可能更新可缓存 KV 或长历史 KV。L0–L1 没有长历史分支； L2/8/14/20 是长历史 KV source，其余 L2+ 读取最近的 source。
关闭 Replay 时，同一次 worker forward 中 L0–L39 使用相同的 scheduled rows， 但各层 attention role 仍按 SWA、长历史 KV 和 source/consumer 关系不同。 全命中时标准前缀复用 t0–t14，仍要执行 t15 以产生 logits；SWA 不会消失， t12–t14 来自 cache，t15 本次执行。
W 是上限：短 Prompt 取 min(query_len, W)，不会补足到 W；Decode 通常只有 1 行，且不继承先前的 replay boundary；prompt_logprobs 保留完整行。 图中的 8/4/16 行是 PCP 的全局逻辑行，不是单个 rank 的本地行数。
