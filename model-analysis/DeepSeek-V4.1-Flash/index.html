0.2 官方信息对照表

模型特性官方信息
模型类型多模态 MoE（image-text-to-text），使用 45T token 多模态语料从头预训练；原生接收图像与文本，生成文本。
语言主干CED 架构：40 层，前 20 层为 causal encoder，后 20 层为 decoder；decoder 的全局 KV 从编码器末端隐状态投影生成。
稀疏注意力CSA2：按层分配 Full / Reindex / Reuse 三种模式，跨层共享主 KV 与 Indexer K，并复用 Top-K 索引；decoder 使用层级稀疏索引器。
激活参数每 token：Prefill 8B / Decode 16B（模型卡统计口径）；两者分别对应输入处理与自回归生成阶段。
上下文长度1M tokens；推荐 context_window=1M，max_tokens ≥ 256K。
KV CacheFP4 主 KV（E2M1 + 每 16 通道一个 E4M3 scale），全局 KV 为 890 bytes/token；SWA Bounded Replay 避免长期持久化 SWA KV，持久缓存约为 V4-Flash 的 1/8。
量化格式checkpoint 使用 FP8 混合精度，weight_block_size=[32,32]、UE8M0 scale；路由专家权重使用 FP4。
推测解码DSpark：3 层半自回归草稿网络，block=5，结合 Markov 头与置信度调度验证。
附加组件Single-Pass mHC（hc_mult=4，Sinkhorn 双随机约束）；Engram 条件记忆（约 196B，通过 n-gram 哈希稀疏查表）。

0.3 目标场景

Agentic 长程任务（主打）：Terminal-Bench 2.1/3.0/4.0 = 90.6/30.0/31.2，DeepSWE v1.1 = 74.2，Agent's Last Exam = 31.8（1M 上下文、max_steps=500 设定），CED 的 8B prefill 激活专门优化输入密集型 agent 工作流。

代码 / 数学：HumanEval 79.4、BigCodeBench 60.6、Codeforces 3471 rating、MathArena Apex 65.6。

多模态：MMMU-Pro 56.5、DocVQA 95.6、RefCOCO-avg 86.0；DeepSeek-ViT 从头训练，2D-RoPE + 3×3 pixel-unshuffle 下采样。

可控推理强度：reasoning_effort 1–100 连续可调，以推理成本换精度。

参数量对账（官方 vs 独立估算）：本报告独立估算总参数 763.36B = Backbone 551.57B + Engram 196.93B + DSpark 14.38B + Vision 0.49B。官方「552B backbone」与独立估算差 0.43B（0.08%），来源为 Engram 表按素数桶 padding 的行数取整与小件舍入；官方口径不含 Engram 与 DSpark 草稿层。

CED 的关键语义：decoder（L20–39）的全局 KV 不是各层各自独立持有，而是由 source layer 产生并被后续层共享。CED 的 encoder/decoder 是层角色与数据依赖划分，不是 phase 级执行裁剪；官方参考实现和 TensorCast trace 在 prefill、decode 中都会按序执行 L0–L39。官方「prefill 8B / decode 16B」属于其激活参数统计口径，不能用“prefill 只执行前 20 层”解释。

2.3 C 类层：decoder r=1 + 层级候选池（L20–39）

L20 的 Compressor 无池化门（r=1 纯投影，bf16 checkpoint），其 Indexer 额外承担候选池生产：select_candidate_blocks 取块最大分 top-2048（块=8 压缩位置，最新块强制保留）→ bool 掩码广播；L24/28/32/36 的 Indexer 在候选池内二次打分取 top-512（两级 top-k）；其余层直接复用。注意力通路、Compressor 通路算子同 A/B 类（引用行）。

Ch 4结构创新带来什么好处

长程 Agent 不断将代码、工具返回和历史交互加入上下文，成本同时来自输入处理、运行时 KV，以及跨轮复用时的缓存保存与搬运。V4.1 将这些成本拆开优化：CED 调整输入计算路径，CSA2 减少重复状态与索引，FP4 缩小单条缓存，Bounded Replay 改变缓存保存与恢复方式，Engram 以稀疏访问扩展记忆容量。

4.1 CED：让长输入的处理成本与输出计算深度分开

机制：decoder 的全局 KV 来自 encoder 末端表示，不再必须等待每个 decoder 层对完整前缀逐层计算，才能得到该层所需的长程状态。这为输入阶段与生成阶段采用不同执行策略提供了条件。

价值：面向长输入，优化调度可让完整前缀主要经过 encoder；decoder 仅对末尾窗口重放以准备局部 SWA 状态。生成新 token 时仍使用完整主干，在降低输入处理开销的同时保留生成阶段的计算深度。

适用场景：大量工具结果回填、长代码上下文、长文档和多轮 Agent。输入 token 远多于输出 token 时，减少 Prefill 工作更容易影响单次请求成本与首 token 延迟。

优化路径的主干 token-layer 工作量示意：
完整前缀逐层处理：N × 40
Encoder 全前缀 + Decoder 末窗口：N × 20 + W × 20，W=128
当 N ≫ W 时，主干层计算可接近原来的一半；全局 KV 投影、索引、通信和恢复开销另计。

该式描述文章中的 CED + Decoder SWA Bounded Replay 优化路径，不是实际时延倍率。仓库参考 forward 在 Prefill / Decode 均遍历全部 40 层；实现上述收益需要相应的 Prefill 与窗口重放调度。

4.2 CSA2：沿“层”减少重复缓存与检索

少保存：长程状态只由少数层持有

40 层主干只有 4 个 Full 层生产并持有长程 main KV 与 index K：encoder 的 L2/L8/L14 和 decoder 的 L20。后续层共享这些物理状态，而不是每层各存一份。

这让 KV 优化从“每条记录更短、每段序列更少”进一步扩展到“层间副本更少”，减少长上下文显存、持久化容量和 KV 写入。

少重做：索引可以刷新，也可以直接复用

Reindex 复用 KV 与 index K，但用当前层查询重新选择 top-k；Reuse 连 top-k 也直接复用。主干共 4 个 Full、4 个 Reindex、30 个 Reuse，另有 2 个纯 SWA 层。

这在保留部分层重新检索能力的同时，避免每层重复计算压缩表示与稀疏选择。每层仍执行自己的 Q/O 投影、SWA 和 MoE。

层级索引：把深层重检索限制在候选集合内

L20 从全局位置产生最多 2048 × 8 = 16,384 个候选位置，后续 Reindex 层在该集合内选取 top-512。在百万 token 场景下，候选范围远小于完整历史，可限制深层索引的计算与访存增长。

首轮全局检索仍随上下文增长。要兑现后续层的计算节省，内核应只评分候选行；参考实现的“全量打分后 mask”表达了选择规则，但仍计算候选域外的分数。

4.3 FP4 KV：让长上下文“存得下、搬得动”

CSA2 减少长程状态的份数，FP4 则进一步减小每份状态。主 KV 使用 E2M1 值与 group-16 E4M3 scale；index K 使用 group-32 E8M0 scale。四个 source 的压缩比例为 [2,2,2,1]，折算到每个输入 token：

main KV：(512×0.5 + 512/16) × (1/2+1/2+1/2+1) = 720 bytes/token
index K：(128×0.5 + 128/32) × (1/2+1/2+1/2+1) = 170 bytes/token
全局 KV 合计：890 bytes/token

价值：全局 KV 约降至 V4-Flash 的 1/4。在 1,048,576 tokens 下，全局 KV 及其 scale 为 0.933 GB / 序列。它减轻 HBM 容量和跨层级搬运压力，为长上下文和更多并发请求释放状态预算。

这里计算的是全局 KV，不包含模型权重、SWA、索引与工作区。低精度缓存是存储格式；使用时可融合反量化后计算 attention，不等于要求所有 attention 运算采用 FP4。

4.4 Engram：在 MoE 之外增加一条稀疏记忆路径

机制：以 2/3/4-gram token 组合确定哈希地址，只读取所需记忆条目，再通过上下文门控注入残差流。V4.1 在 L1、L14 设置两个 Engram 模块，总表容量约 196B 参数；每层每 token 访问 24 行记忆。

价值一：容量与计算量不必同比增长。扩大表容量主要增加可保存的模式与知识条目，不需要每次对整张表做稠密计算。每 token 仍只访问少量行，扩容压力更多落在存储而非全表矩阵乘。

价值二：让知识读取与复杂计算分工。MoE 选择“调用哪些专家”，Engram 选择“读取哪些记忆”；前者提供条件计算，后者为已学习的局部模式提供直接读取通道，两种稀疏性相互补充。

价值三：地址可预测，便于提前搬运。哈希地址由 token 决定，可在抵达注入层前预取，与其他层计算重叠。采用主机驻留时，这为利用大容量主机内存、缓解设备 HBM 压力提供了条件。

大表仍需真实存储；收益取决于随机读取、预取重叠与通信效率。设备常驻偏向低延迟，主机驻留偏向容量；参考实现的设备分片表与文章描述的主机预取属于不同部署选择。

4.5 Single-Pass mHC 与 DSpark：减少执行过程中的额外开销

Single-Pass mHC：把依赖调整为可融合的数据流

当前子层读取上一个子层已生成的 pre_mix，避免输入混合等待当前系数完成全维归约。融合内核可以更紧密地合并残差更新、流归约、系数预测与归一化，减少中间结果读写和 kernel 启动。

收益集中在激活访存与执行开销，尤其适合小 batch Decode；它仍保留 4 路残差与 Sinkhorn 混合的表达能力。

DSpark：用一轮验证摊薄多个输出 token 的成本

轻量草稿网络给出多个候选 token，再由目标模型验证；Markov 头与置信度帮助组织 proposal 和验证长度。接受的候选越多，目标模型单次验证成本能分摊到的有效输出越多。

收益集中在生成阶段的单位 token 成本；实际加速由草稿开销、接受长度、验证效率和在线负载共同决定，block=5 不等于固定 5 倍速度。
